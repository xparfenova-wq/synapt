# Как править сайт Synapt

Живой сайт: https://synapt.tech
Всё, что лежит в папке `site/`, попадает на домен автоматически: сервер забирает изменения из ветки `main` раз в две минуты.

## Быстрый порядок работы

1. Правим нужный файл
2. `git add -A && git commit -m "что поправили" && git push`
3. Через пару минут открываем страницу и проверяем

## Страницы услуг и кейсов: пока правим напрямую в site/

Генератор `builder/` (specs.json + build.py + publish.py) отстал от живых страниц: с 16 по 18 августа страницы услуг и кейсов правились напрямую в `site/`, в генератор эти правки не перенесены. Поэтому сейчас:

- правим `site/desant/`, `site/globaldent/`, `site/innorto/`, `site/safe/`, `site/prodazh/` напрямую в файле, как и остальные страницы
- `python3 builder/publish.py` НЕ запускаем: он соберёт старую версию и перезапишет живые страницы. Скрипт остановлен предохранителем и без флага `--force` ничего не делает
- когда генератор пересинхронизируют с site/, этот раздел вернётся к порядку «правим specs.json → publish.py»

Единые правила иерархии, добавленные 18.08 в конец `<head>` каждой страницы блоком `<style id="hier-fix">`: копирайт 13.5 (13 на телефоне), блок «Другие услуги и кейсы» с кикером «NN Ещё у студии» и заголовком h2, одинаковая сетка карточек, блок стоимости одной раскладки на всех страницах

## Правила

- Стиль, кегли, палитра и типографика описаны на https://synapt.tech/content
- Внутренние ссылки только относительные: `/checkup/`, `/desant/`
- Ничего не удаляем из `site/` просто так: страница пропадёт с домена в ближайшие две минуты
- Перед пушем открываем файл в браузере и смотрим глазами

## Откат

- Сервер снимает бэкап перед каждой выкладкой, последние десять лежат в `/var/www/_backups/`
- Через git: `git revert <коммит>` и пуш
